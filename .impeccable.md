## Design Context

### Users
Players of MythWar Online on the osMW private server who run osMW Maps++ as a background companion app alongside the game client, often while multi-boxing several game windows at once. They interact with these WebView2 panels (tray menu, settings, client roster/radial, map POI editor, window-layout prompt) in short bursts between or during gameplay, not as a primary destination — glances and quick edits, not extended sessions.

### Brand Personality
Clean utility app. Not trying to look "gamer" or use game-HUD styling — closer to a well-made desktop settings/admin panel: organized, legible, low-drama. Solo-developer project (single maintainer), so consistency and low maintenance overhead matter more than novel visual flourishes.

### Aesthetic Direction
Existing direction in `ui/common/style.css` — dark theme only (charcoal/slate surfaces, a selectable amber/blue/green accent with warm amber-gold as the default, Inter body font, Material Symbols icons), frameless custom title bars, dense data tables. No light theme exists or is planned; the app is always used in a dark, in-game context, so a single dark theme is intentional rather than a gap. Continue and reinforce this existing system rather than introducing a second theme or a different visual language per panel.

### Design Principles
1. One dark theme via CSS custom properties in `ui/common/style.css`, shared by every panel — don't hard-code one-off colors per panel.
2. Practical accessibility bar, not formal WCAG AA/AAA: fix real usability problems (illegible contrast, unusable keyboard flow, unlabeled controls) but don't grade against public-web compliance targets — this is a local, single-user desktop tool, not a public web product.
3. Dense, table/form-heavy utility UI is appropriate here; don't push it toward card grids or marketing-page patterns.
4. Keep panels consistent with each other (buttons, inputs, badges, tables already share classes in `common/style.css`) — flag drift, not variety for its own sake.
