osmw_fishing.dll
================

Purpose
-------
Presents the server-authoritative fishing minigame as a 456x280 modal instead
of the stock npclessSay dialogs. The module never rolls a catch, never spends
bait, and never decides a result. It only renders the last valid snapshot and
queues one command per revision.

It is a managed ABI 1 feature. Core owns UiTick, HandlePacket, and the send
queue. This DLL claims 0x7F000041 exclusively, observes MapData after stock,
and creates or destroys its node only from a post-UiTick callback. There is no
main.exe cave patch and no shared-hook claim.

Gate
----
[Addons] Fishing=1 (default). Fishing=0 returns OSMW_MOD_DISABLED before any
signature resolve. The DLL is only loaded when [Core] Modules= lists
osmw_fishing.dll. A game-folder defaults.ini that omits it wins over the
compiled fallback, so a copied DLL stays inert and fishing stays on stock
npclessSay. Absence of the DLL must not cost a stock client anything: the
server keeps the existing dialog path until a v1 hello is accepted.

Protocol
--------
Hello     C2S 0x7F000040  16 bytes, protocol DWORD at 12, no extra.
Snapshot  S2C 0x7F000041  128 bytes, extra 112. Consumed even when ignored.
Action    C2S 0x7F000042  28 bytes, extra 12: command, session, revision.

Snapshot extra (offsets from extra[0], which is packet offset 16):

  0 phase u8, 1 hint u8, 2 progress u8, 3 tension u8
  4 session u32, 8 revision u32
  12 roundsRemaining u8, 13 maxRounds u8
  14 speciesIndex i8 (-1 hidden; 0-9 only on Land)
  15 flags (canCast=1, overCap=2, newLogEntry=4)
  16 baitCount u16, 18 fishingLevel u8, 19 pad
  20 fishingXp u32, 24 nextLevelXp u32, 28 collectionMask u32
  32 message[80] NUL-terminated

Commands: Cast=1, ReelLeft=2, ReelRight=3, Hold=4, Slack=5, PackUp=6.
v1 only. Unknown versions, wrong sizes, and out-of-range fields are consumed
and ignored. A newer revision unlocks input; the same revision stays locked.

UI
--
Centered 456x280 at (172,160)-(628,440). Frame tiles 55 x 33, which is why
those dimensions are not free choice (16px corners, 8px edge pieces).

Four 96x24 buttons at y+200. Hooked: Reel Left / Reel Right / Hold / Slack.
Ready and result phases: Cast (if canCast) in slot 0, Pack Up in slot 3.

Clicks: 0xF5 down, consume EventCode, one-shot arm so a held button is not a
repeat. Disable immediately after a queued action; re-enable only when a
newer valid snapshot arrives.

Artwork
-------
Optional system\osmw_fishing.mda via LoadMda / BlitMda. Animation names:

  Casting, ThrashLeft, ThrashRight, Snap, Escape, Shadow, Reveal0-Reveal9

A miss of either signature, a NULL load handle, or a blit that returns 0
keeps the same geometry and hitboxes and draws text/arrows instead. The packed
bank is copied to Lib/osmw_fishing.mda and into the client's system\ folder on
deploy and Maps++ launch. The first blit refusal is logged once.

Lifecycle
---------
World entry and MapData both queue Hello from the following post-tick, never
from the observer. Leave-world (GridScaleX==0), Closed snapshots, shutdown,
and protocol loss destroy the node. Hello retries on a 500 ms bound.

Signatures (15, 3 optional)
---------------------------
UiCreateNode, UiDestroyNode, NodeGeometry, NodeSetGeometry, DrawText,
DrawCtx, DrawInfoBox, InfoFrames, EventCode, GridScaleX, MouseX, MouseY,
LoadMda (optional), BlitMda (optional), TextWidth (optional).

Reference RVAs are in src/sigs.h. Core's resolver is the only scanner.
UiTick / HandlePacket / SendPacket are deliberately not requested.
