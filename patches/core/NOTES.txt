ABI 1.0 decisions
-----------------

* x86 Windows only, MSVC /MT.  The public header fails at compile time when a
  pointer is not 4 bytes.
* Every cross-DLL function is __cdecl.  Raw client conventions such as the
  __stdcall HandlePacket boundary remain private to the core.
* DWORD/LONG typedefs and numeric macros are used instead of compiler-sized
  enums.  OSMW_RESULT is a signed LONG.
* Public structures are #pragma pack(push, 4), size-prefixed and append-only
  within ABI major 1.
* No CRT allocation, FILE pointer, C++ object, varargs, or ownership-bearing
  string crosses the boundary.
* Owner and resource tokens are opaque nonzero DWORDs, never pointers.
* A module exports one permanent, side-effect-free query function.  Its .def
  file keeps osmw_mod_query undecorated.
* Query returns a descriptor containing init/shutdown pointers.  Modules do not
  link an import library; core passes its function table into init.
* A managed module's DllMain is passive.  The fixture is the reference shape:
  DisableThreadLibraryCalls and return.


Frozen x86 layouts
------------------

  OSMW_SIGNATURE_V1          32 bytes
  OSMW_RESOLVED_ADDRESS_V1   24 bytes
  OSMW_REGION_CLAIM_V1       24 bytes
  OSMW_GAME_PACKET_V1        20 bytes
  OSMW_MODULE_STATUS_V1     192 bytes
  OSMW_MOD_DESCRIPTOR_V1     32 bytes
  OSMW_CORE_API_V1           72 bytes

test_api_layout.c asserts both every total above and the offsets of the fields
that define each structure's prefix/tail.  Compile that same source as /TC and
/TP; this proves the header remains valid C and C++ while the implementation
stays C.


Managed bootstrap core
----------------------

* DllMain disables thread notifications, starts one bounded worker, and
  returns without installing hooks or touching client memory.
* The worker resolves the game directory from GetModuleFileNameA(NULL), starts
  config/tagged-log services, reads and validates its exact process executable
  into the pristine-image service, starts the signature cache, attempts the
  single core-owned UiTick hook, processes the managed module manifest, and
  returns.
* The sole export is the exact undecorated name osmw_prepare_unload.  It asks
  the worker to stop, joins it outside the loader lock, runs the currently
  managed core shutdown, and returns zero only when FreeLibrary is safe.
* tools/build.py builds x86 with MSVC /MT /W4 /WX, verifies the PE machine,
  DLL flag, import set, and exact export set, then writes the modhash stamp.
* modhash covers both core/src and the frozen core/sdk header.  build.ps1 puts
  core first in the native rebuild sequence.


Config and tagged logging
-------------------------

* Every read follows config.ini -> defaults.ini -> the caller's literal.
  A present but invalid integer does not silently expose the default beneath
  it; it uses the caller literal, matching the existing feature DLLs.
* String reads always NUL-terminate a nonempty output buffer and return
  OSMW_E_BUFFER_TOO_SMALL when truncated.
* Writes use WritePrivateProfileStringA against config.ini only.  The core
  never mutates defaults.ini.
* Owner handles map to validated stable module ids.  Config and log entry
  points reject unknown handles; log callers cannot supply their own tag.
* [Debug] ModLogging=1 opens osmw_core.<pid>.log.  Off creates no file and
  removes old core logs.  On retains five old logs before creating the current
  one, matching the existing per-module behavior.
* Lines carry time, level, and module id.  Embedded CR/LF is flattened so one
  message cannot forge an untagged line.  The log closes with a diagnostic at
  the same 1 MB cap used by the current native logs.


Pristine image and signatures
-----------------------------

* image.c reads the exact path returned by GetModuleFileNameA(NULL) once with
  full file sharing, then retains that immutable allocation until shutdown.
* The parser requires a bounded x86 PE32 executable, validates the complete
  header/section table and every raw/virtual section range, rejects header
  overlap, and requires exactly one executable-code .text section.
* The retained view records raw .text, preferred and loaded bases, timestamp,
  and SizeOfImage.  A base mismatch retains diagnostics but makes every
  address request return OSMW_E_UNAVAILABLE.
* scan.c accepts the generated pattern/mask/length/op-offset shape.  It reports
  zero and two-or-more matches distinctly and reads absolute DWORD operands
  from pristine bytes, never the potentially patched live image.
* Successful, missing, and ambiguous requests are cached by pattern, mask, and
  operand offset.  The cache owns copies of its keys; caller buffers may go
  away as soon as resolve_signature returns.
* reference_rva is the expected resolved-address RVA.  match_rva separately
  reports where the pattern was found.  This distinction preserves the
  existing generated-table meaning for absolute-operand signatures.
* Fixture coverage carries one byte-for-byte generated signature shape from
  each of chatmod, login, minimap, fightspeed, weather, settings, and timers.


Managed module loader
---------------------

* loader.c reads [Core] Modules through the normal config fallback chain.  Its
  compiled order is chat, login, minimap, fightspeed, weather, settings, then
  timers.  It never wildcard-scans the game directory.
* Manifest entries must be unique bare DLL filenames.  Absolute/traversal
  paths, separators, non-DLL names, and osmw_core.dll are rejected before any
  filesystem load operation; accepted names become absolute game-root paths.
* A bounded PE32 parser validates each candidate's headers, raw sections, DLL
  flag, and export-name table before LoadLibrary.  The exact undecorated
  osmw_mod_query export is mandatory.
* Managed query/descriptor ABI, module id, display name, lifecycle pointers,
  and required ABI are validated before an owner is issued.  Duplicate module
  ids and incompatible modules are passively unloaded.
* Init runs serially in manifest order through one immutable 72-byte API table.
  Missing, legacy, incompatible, loaded, active, disabled, failed, stopping,
  unsafe, and unloaded states are retained in core-owned status snapshots.
* A failed init is unloaded only with zero owned resources.  Runtime claims,
  post-UiTick subscriptions, typed packet registrations, and copied queued
  sends are operational whenever their capability bits are present.
* The loader fixture builds active, disabled, failed, duplicate-id,
  incompatible, and legacy DLLs.  The legacy DllMain would create a marker on
  process attach; the test proves that marker is absent and the DLL is never
  mapped.  It also proves serial init, reverse shutdown, retained statuses, and
  clean unload of every passive rejection/failure.


Exclusive runtime claims
------------------------

* claims.c grants nonzero, readable address/length ranges with a validated
  CODE, CALL_SITE, IAT, or DATA kind and a copied diagnostic label.  Both
  feature modules and the core owner use this one registry.
* ABI 1 keeps 256 simultaneous claim records, comfortably above the current
  116 total signature sites even if every site became a separate claim.  A
  full registry returns OSMW_E_BUSY without changing existing ownership.
* Every grant snapshots the live bytes with ReadProcessMemory.  No core claim
  API writes the target; specialised patch engines remain module-owned.
* Ranges are half-open.  Exact, contained, containing, left-edge, and
  right-edge overlaps are rejected regardless of kind; ranges that touch only
  at an endpoint are legal.
* Collision logs name both owners, labels, addresses, and lengths.  Unsafe
  unload diagnostics enumerate each retained label, kind, range, and token.
* Release validates the owner and compares live bytes with the snapshot.
  Changed or unreadable bytes return OSMW_E_PATCH_STILL_ACTIVE without
  discarding the token; wrong-owner and repeated releases also fail closed.
* Module status reports the current owned-claim count.  Whole-core prepare now
  propagates an unsafe loader result rather than telling the injector to call
  FreeLibrary while a claim-owning module remains mapped.
* test_claims.c exercises invalid inputs, all overlap geometries, legal
  adjacency, core-vs-module collision, wrong-owner/repeated release, snapshot
  restoration, diagnostic text, and status counts.  fixture_unrestored.dll
  deliberately leaves one byte changed on its first shutdown: whole-core unload
  is refused, both it and a clean companion stay mapped, and a restored-byte
  retry unloads the complete set without calling the clean shutdown twice.


Shared UiTick and packet brokers
--------------------------------

* signatures.ini owns the three proven UiTick, HandlePacket, and SendPacket
  patterns copied from timers.  tools/scan_offsets.py requires one match in
  the installed main.exe and regenerates src/sigs.h without writing a runtime
  address cache.  All three resolve once on build 0x45650696 at RVAs 0x5E7B0,
  0x542C0, and 0x54060 respectively.
* Core startup resolves those definitions through the retained pristine-image
  API, then attempts one seven-byte UiTick detour and one 12-byte HandlePacket
  detour before module init.  OSMW_CAP_UI_TICK and OSMW_CAP_GAME_PACKETS are
  advertised independently only while their hook is active.  A missing,
  ambiguous, relocated, or already-modified target leaves stock code untouched
  and makes that service return OSMW_E_UNAVAILABLE; unrelated services and
  modules can still start.  OSMW_CAP_SEND_QUEUE additionally requires a
  resolved SendPacket address and the UiTick hook that owns game-thread flushes.
* hook.c copies the exact prologue from the pristine image, builds a
  position-independent-prologue trampoline, publishes that original before the
  detour becomes reachable, and owns the target through the Task 6 claim
  registry.  The live prologue must equal those pristine bytes exactly.  A
  pre-existing E9 or any other change is refused; core never recreates the
  legacy arbitrary hook chain.
* Multi-byte writes use the proven freeze/check/write sequence: make the page
  writable, suspend up to 64 peer threads, inspect control contexts, require
  every EIP outside the target, write and flush while frozen, then thaw.  A
  busy or unreadable region is retried 100 times and then left untouched.
* Removal checks the target, trampoline and a conservative detour-code range,
  plus an atomic count covering every live detour entry, before restoring the
  original prologue.  It verifies that the target is still core's own patch
  and releases the ownership claim only after the snapshotted bytes are back.
* dispatch.c keeps 64 owner-scoped post-UiTick registrations.  The public API
  rejects negative priorities, uses zero as the feature default, and issues
  opaque unsubscribe tokens.  Each pass calls stock exactly once, then uses a
  stable ascending-priority/registration-order callback snapshot without the
  registry lock.  Add/remove during a callback is deferred to the next pass.
* Packet dispatch keeps up to 64 exclusive exact-type handlers and 128 ordered
  post-stock observers in the same owner/token namespace.  A PASS, absent, or
  invalid handler result reaches the raw __stdcall stock dispatcher exactly
  once; invalid values are logged.  CONSUME skips stock and every observer.
  Plugin callbacks stay __cdecl and receive a stack view of borrowed payload
  storage that the core never retains.
* The send queue has the ABI-named limits OSMW_SEND_QUEUE_CAPACITY=32 and
  OSMW_SEND_PACKET_MAX_EXTRA=4096.  queue_game_packet copies bytes under the
  registry lock before returning.  Full and oversized requests fail with
  OSMW_E_QUEUE_FULL and OSMW_E_BUFFER_TOO_SMALL.  A fixed-start-of-flush budget
  preserves FIFO order and defers sends recursively queued by SendPacket until
  the next tick; packets queued by module callbacks are included in the current
  tick's flush after all post-UiTick callbacks.
* A manual-reset quiescence event and in-flight count make shutdown bounded.
  Once stopping begins, new entries still call the stock original but start no
  module callbacks; core teardown refuses to proceed while an earlier callback
  remains in flight.
* Managed shutdown is two-phase.  Modules are stopped in reverse order and
  retained in OSMW_MODULE_STOPPING until every owner has zero subscriptions and
  claims.  Any unsafe owner aborts the commit before the first managed
  FreeLibrary; retry calls only unsafe shutdowns, then unloads the complete
  clean set in reverse before removing the core hooks and services.
* test_dispatch.c is linked as test_broker.exe because Windows UAC installer
  detection treats an executable name ending in "patch" as an installer.  It
  executes generic and UiTick-shaped x86 trampolines, exercises the immutable
  API table and capability, rejects prepatched/tampered targets, parks a peer
  EIP inside a write range, verifies original-once callback order and safe
  self-unsubscribe, mutates subscriptions from a callback, and proves an
  in-flight callback prevents trampoline reclamation until quiescence.
* test_packets.c executes generated UiTick and HandlePacket-shaped x86 targets.
  It verifies the raw ret-0x10 boundary with ESP and stack canaries, unchanged
  stock arguments, exact-type PASS/CONSUME/invalid-action behavior, stable
  post-stock ordering, wrong-owner/exclusive tokens, borrowed receive storage,
  synchronous queue copying and limits, FIFO order, and UiTick-thread flushing.

Build and run all current core fixtures with:

  python patches/core/tools/build.py --test --no-deploy

The lifecycle fixture performs 25 immediate LoadLibrary / prepare / repeated-
prepare / FreeLibrary cycles, exercising the startup-worker join and idempotent
successful prepare path.
The test runner also launches a copied real core DLL beside an opt-in
config.ini and checks its tagged image-ready/startup/shutdown log.  Neither
substitutes for the still-pending live-client inject/eject check.


Manual Task 1 verification
--------------------------

Run these from a Visual Studio x86 developer prompt, with patches/core/build
already created:

  cl /nologo /W4 /WX /MT /TC /I patches\core\sdk patches\core\tests\test_api_layout.c /Fo:patches\core\build\test_api_layout_c.obj /Fe:patches\core\build\test_api_layout_c.exe

  cl /nologo /W4 /WX /MT /TP /I patches\core\sdk patches\core\tests\test_api_layout.c /Fo:patches\core\build\test_api_layout_cpp.obj /Fe:patches\core\build\test_api_layout_cpp.exe

  cl /nologo /W4 /WX /MT /LD /I patches\core\sdk patches\core\tests\test_module_fixture.c /Fo:patches\core\build\test_module_fixture.obj /link /MACHINE:X86 /DEF:patches\core\tests\test_module_fixture.def /OUT:patches\core\build\test_module_fixture.dll /IMPLIB:patches\core\build\test_module_fixture.lib

  cl /nologo /W4 /WX /MT /I patches\core\sdk patches\core\tests\test_host_fixture.c /Fo:patches\core\build\test_host_fixture.obj /Fe:patches\core\build\test_host_fixture.exe /link /MACHINE:X86

Then run:

  patches\core\build\test_api_layout_c.exe
  patches\core\build\test_api_layout_cpp.exe
  patches\core\build\test_host_fixture.exe \
     patches\core\build\test_module_fixture.dll

The host fixture deliberately uses LoadLibraryA + GetProcAddress by the exact
string "osmw_mod_query".  That makes a decorated export fail the test rather
than becoming a loader bug later.
